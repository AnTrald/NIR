## Предлагаемая локальная топология

Три сервиса: frontend (Next.js), backend (FastAPI), db (PostgreSQL). Наружу на loopback публикуется frontend; API и БД остаются во внутренней сети Compose. Next.js проксирует фиксированные `/api/*` и `/preview/runner`. Volume хранит данные PostgreSQL; миграции запускаются явной одноразовой командой сервиса backend. Миграция должна завершиться до обслуживания пользовательских запросов, а не выполняться независимо каждым worker.

Предлагаемые переменные: `APP_ORIGIN`, `DATABASE_URL`, `SESSION_COOKIE_SECURE`, `SESSION_TTL_SECONDS`, `CSRF_PREAUTH_TTL_SECONDS`, `MARKDOWN_IMAGE_ORIGINS`, `LOG_LEVEL`. `.env.example` описывает поля без настоящих секретов. Секреты не попадают в NEXT_PUBLIC, frontend bundle, логи или Git. Конкретные значения и версии будут выбраны перед установкой.

Локальный HTTP-профиль ограничивается 127.0.0.1; аутентификация и cookie-режим будут реализованы на этапе 3. Нелокальная эксплуатация требует HTTPS и Secure cookies; её настройка не является уже выполненной частью MVP. Docker Engine 28.0.4 доступен с расширенным доступом и контекстом desktop-linux. Все три сервиса запускались и получили healthy. Docker inspect подтвердил: backend/db не публикуют порты, frontend публикует только 127.0.0.1:3000. У backend runtime user notebook, у frontend — node.

## Текущее состояние исходных файлов этапа 1

Frontend содержит Next.js App Router, строгий TypeScript, Tailwind CSS, начальную страницу и компонент реальной проверки /api/health/ready. Фиксированный rewrite /api/* ведёт к одноимённым путям backend:8000, включая Swagger /api/docs и схему /api/openapi.json. Внутренние алиасы /health/ready и /health/live сохранены для Docker и не включены в OpenAPI. Путь /preview/runner только зарезервирован проксированием; сам runner появится на этапе 6 и сейчас возвращает 404.

Backend содержит FastAPI lifespan, SQLAlchemy engine, безопасные ответы ошибок, liveness и readiness с SELECT 1. Alembic настроен; бизнес-моделей и ревизий миграций пока нет — это этап 3. Явный запуск alembic upgrade head перед приложениями выполнен; alembic current и alembic check прошли. Последовательность описана в [README](../README.md).

Compose определяет ровно три сервиса db/backend/frontend. Только frontend публикуется на 127.0.0.1:3000, для PostgreSQL задан named volume /var/lib/postgresql. Dockerfile frontend/backend используют непривилегированного пользователя для runtime. Запуск и порты проверены фактически. docker-compose.test.yml — дополнение для отдельного тестового образа backend через compose run; production-контейнер не заменяется. После тестов работающие сервисы оставлены для локального просмотра.
