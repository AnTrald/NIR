# Этап 2 — формат `.webnb`

Дата: 21 ноября 2026 года.

**Проверки формата пройдены.** После закрепления Rolldown 1.2.19 в devDependencies Windows-запуск Vitest дал 92 passed. Python-набор notebook_engine в Docker без сети дал 93 passed, в том числе исправленный pointer-escape. Оба набора включают 87 общих сценариев. `npm run check:webnb` подтвердил соответствие типов и валидаторов схеме. Vite предупредил о будущем изменении загрузчика конфигурации. Production-сборка и E2E в этот прогон не входили. Разбор движка возобновлён, проверка понимания ожидает сигнала заказчика. Ниже сохранена история проверок.

## Повторные проверки по поручению заказчика

**Последняя попытка после установки optional-зависимостей.** В lock-файле отсутствовали записи платформенных пакетов Rolldown 1.2.19. Недостающие записи восстановлены без изменения существующих версий. Чистая установка из обновлённого файла завершилась успешно (163 пакета), но прямой импорт Windows-модуля вернул MODULE_NOT_FOUND и Vitest вновь остановился до запуска тестов. Рекомендуемый следующий шаг — закрепить Rolldown 1.2.19 как прямую dev-зависимость и проверить чистую установку. Генератор ожидаемых JSON Pointer исправлен, 87 сценариев перегенерированы. Новый pytest не стартовал из-за недоступности Linux Engine Docker Desktop. Числа 92/1 ниже относятся к предыдущей попытке. Объяснение движка отложено по просьбе заказчика до исправления тестов.

21 ноября 2026 года заказчик поручил повторить тесты, затем подробно объяснить `notebook_engine` и ввести постоянное правило проверки понимания ключевых блоков.

- `npm.cmd run test:unit` из `frontend`: код 1, прежняя ошибка загрузки native binding Rolldown; ни один frontend-тест не выполнен. Успешность переустановки зависимостей пользователем не предполагается без подтверждения.
- Python: `pytest -q -p no:cacheprovider tests/test_notebook_engine.py` в существующем тестовом образе с актуальными исходниками, schema и fixtures, подключёнными только для чтения; `--network none`, без БД. **92 passed, 1 failed**, 3,26 секунды.
- Единственное падение — `pointer-escape`: fixture ожидает `/cells/0/metadata/a~/b`, движок возвращает `/cells/0/metadata/a~0~1b`. Для имени ключа `a~/b` JSON Pointer требует заменять `~` на `~0`, `/` на `~1`; фактический путь корректен. В генераторе fixtures ожидаемый путь построен простым соединением сегментов без экранирования.
- Остальные 86 общих сценариев и 6 дополнительных Python-проверок прошли, включая соответствие модели schema, ограничение сообщений об ошибках, отсутствие изменения входа, повторную проверку перед записью, отклонение циклов, изолированный импорт и round-trip без приложения/БД/сети.

После обнаружения ошибок реализация и зависимости не изменялись. Рекомендуется согласовать исправление экранирования ожидаемого пути в генераторе fixtures с их перегенерацией, а для Rolldown — диагностику платформенного optional-пакета. Альтернатива для frontend — тестирование в Linux-контейнере; смена версии Vitest остаётся запасным вариантом. Backend-инфраструктурные тесты, E2E и production-сборка в этом повторном запуске не выполнялись.

Правило разбора и проверки понимания записано в [AGENTS.md](../AGENTS.md). Подробное объяснение `notebook_engine` начинается в чате после этого запуска. Заказчик ещё не сообщил, что объяснение завершено; тест на понимание не начат.

## Цель и критерии

Реализовать строгий переносимый `.webnb` 1.0 по [спецификации](notebook-format.md) и P-003 из [решений](decisions.md): Pydantic-модели, общую JSON Schema, TypeScript-типы и валидацию, нормализацию, сериализацию и десериализацию. Критерий — чтение и запись с сохранением содержимого, порядка и активности ячеек, одинаковыми ограничениями и ошибками в Python и TypeScript.

## Подготовленные изменения

- `backend/notebook_engine/`: строгие модели, ошибки с JSON Pointer и русскими сообщениями, чтение UTF-8/JSON, проверка глубины и повторных ключей, нормализация, запись и подготовка данных к хранению. Зависимости пакета — стандартная библиотека и уже установленный Pydantic. Изолированная работа ещё должна быть подтверждена тестом.
- `schemas/webnb-1.0.schema.json`: JSON Schema 2020-12, экспортированная из моделей. Расширение OpenAPI `discriminator` удаляется из переносимой схемы. Подготовлен тест точного соответствия экспорта зафиксированному контракту.
- `frontend/src/lib/notebook/`: JSON parser, ошибки, проверка структуры и семантики, нормализация и сериализация. `generated/` содержит типы и заранее скомпилированные Ajv-валидаторы из общей схемы. Во время работы в браузере генерация функций не требуется.
- `frontend/scripts/generate-webnb.mjs`: генерация и режим `--check` для выявления рассинхронизации с общей схемой.
- `contracts/webnb/cases.json`: 87 общих сценариев; большие документы представлены компактными рецептами. Ожидаемые размеры и SHA-256 корректной сериализации вычислены независимым скриптом `scripts/generate-webnb-fixtures.py`, без импорта движка.
- Подготовлены pytest/Vitest-проверки общих сценариев, повторного чтения, сохранности `source` и порядка, нормализации без изменения входа, ограничения ошибок, повторной валидации перед записью, циклических данных. Отдельно подготовлены Python-тест изоляции от приложения/БД/сети и TypeScript-тест против загрязнения `Object.prototype`.
- Backend Dockerfile включает пакет в runtime-образ. Тестовый Compose подключает fixtures и schema только для чтения.
- В frontend зафиксированы Ajv 8.20.0, json-schema-to-typescript 16.0.0 и Vitest 5.1.1; обновлён lock-файл. Новых Python-зависимостей нет.

Это подготовленная реализация, а не подтверждение её корректности. Интерфейс импорта/экспорта, API хранения и выполнение ячеек относятся к последующим этапам.

## Проблема и варианты продолжения

Vitest завершился на загрузке Rolldown с ошибкой `Cannot find native binding`. В цепочке причин указаны отсутствующие `@rolldown/binding-wasm32-wasi` и `rolldown-binding.wasi.cjs`. Это сбой загрузки зависимости тестового инструмента, до выполнения проверок `.webnb`. Сообщение ссылается на проблему optional dependencies в npm; точная причина отказа нативного модуля отдельно не установлена.

1. **Рекомендуемый вариант:** проверить платформенный optional-пакет Rolldown и восстановить frontend-зависимости командой `npm ci --include=optional`, сохраняя выбранные версии и lock-файл. Затем повторить тесты. Успешность решения пока не проверена.
2. Запускать frontend unit-тесты в отдельном Linux-контейнере Node 24. Потребуется добавить тестовую Docker-конфигурацию; локальный запуск Vitest в Windows останется неисправленным.
3. Подобрать другую совместимую стабильную версию Vitest после проверки документации и зависимостей. Потребуется изменение lock-файла; это запасной вариант.

Удаление lock-файла и `node_modules`, переустановка, смена версии или обход через Docker после ошибки не выполнялись. Работа остановлена по прямому условию заказчика, а не из-за отказа автоматического согласования доступа. Этап 3 не начат.
