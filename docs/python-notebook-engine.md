# Python Notebook Engine

Проверки формата прошли в Python (93 теста) и TypeScript (92 теста). Типы и валидаторы соответствуют JSON Schema. Условия последнего запуска приведены в [отчёте этапа 2](stage-2-report.md).

## Граница пакета

Расположение — `backend/notebook_engine/`. Зависимости — Python, стандартная библиотека и Pydantic. Нет импортов FastAPI, SQLAlchemy, HTTP-клиента, подключения к БД или обязательных переменных окружения. Импорт пакета не запускает сервисы.

Пакет обрабатывает только переносимый документ, не пользователей, владельцев, HTTP-статусы и revision БД. FastAPI переводит его предметные ошибки в API-ошибки. Сетевые URL в коде/Markdown не загружаются сервером.

## Предлагаемые операции

| Операция | Вход → результат |
| --- | --- |
| `parse_document` | UTF-8 bytes → проверенная нормализованная модель |
| `validate_document` | Разобранные недоверенные данные → модель или ошибки |
| `normalize_document` | Проверенная модель → модель с явными defaults |
| `serialize_document` | Модель → переносимые UTF-8 bytes |
| `prepare_for_storage` | Модель → JSON-совместимые данные и метаданные |

Эти функции подготовлены на этапе 2; результаты выполненных проверок приведены выше. `parse_document` проверяет число байт, UTF-8, JSON-глубину, повторные ключи и запрещённые числа до Pydantic. API также должен сохранять проверку повторных ключей до стандартного разбора request body, иначе информация уже будет потеряна.

Последовательность проверки: предел тела → синтаксис и глубина JSON → корневой формат/версия → строгая discriminated union по `type` → неизвестные поля → строковые и количественные лимиты → ID → нормализация → размер сериализованного документа. Лимит сообщений об ошибках — первые 50 с отдельным признаком усечения.

Сериализация не исполняет код, не рендерит HTML, не изменяет `source`, не делает HTML-экспорт. HTML-экспорт использует Browser Execution Engine. Нормализация идемпотентна; сериализованный документ должен повторно пройти parse/validate.

## Проверки этапа 2

Общий набор fixtures запускается в Python и TypeScript: четыре типа, пустой документ, отключённые ячейки, неизвестная версия, неизвестное поле, `enabled` у Markdown, пропущенный boolean программной ячейки, повторный ID, неправильный тип, дубли ключей JSON, повреждённый UTF-8, Unicode и граничные размеры. Проверяются parse → serialize → parse и совпадение нормализованных результатов.

Тест изолированного импорта пакета проверяет отсутствие FastAPI/SQLAlchemy и обращений к сети/БД. Он прошёл при повторном запуске 21 ноября 2026 года; весь Python-набор пока имеет одно падение, описанное в отчёте.
