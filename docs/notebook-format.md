# Спецификация `.webnb` 1.0

Проверки формата прошли в Python (93 теста) и TypeScript (92 теста). Типы и валидаторы соответствуют JSON Schema. Условия последнего запуска приведены в [отчёте этапа 2](stage-2-report.md).

## Представление и версия

Файл — JSON в UTF-8 без BOM, расширение `.webnb`. Корень — объект. Комментарии JSON, trailing commas, NaN/Infinity, повторные ключи объектов, некорректный UTF-8, одиночные UTF-16 суррогаты и U+0000 запрещены. Повторные ключи проверяются при разборе исходного текста, до потери информации обычным JSON.parse; понадобится соответствующий безопасный parser на клиенте.

`version` — строка с точным значением `1.0`, а не число. Любая другая версия даёт `unsupported_version`: документ не открывается с частичной потерей данных. Автоматической миграции пока нет. Будущая миграция будет отдельной явной операцией с новыми fixtures.

| Поле корня | Тип и правило |
| --- | --- |
| `format` | Обязательная строка `web-notebook` |
| `version` | Обязательная строка `1.0` |
| `metadata` | Обязательный объект метаданных документа |
| `cells` | Обязательный массив 0–200 ячеек; порядок значим |

Другие поля запрещены на каждом уровне. `null` не заменяет отсутствие необязательного поля. Типы строгие, строка `"true"` не является boolean.

## Метаданные документа

| Поле | Правило |
| --- | --- |
| `title` | Обязательная строка 1–200 Unicode scalar values; не состоит только из ASCII-пробелов U+0020 и U+0009–U+000D |
| `description` | Необязательная строка 0–2000 символов; при отсутствии нормализуется в `""` |

Пробелы и переносы исходных строк сохраняются. Нормализация не переписывает Markdown, код или переносы строк. Поля `owner_id`, `revision`, внутренний ID документа, даты сервера, результаты выполнения, пароли и сессии не входят в формат.

## Ячейка

| Поле | Правило |
| --- | --- |
| `id` | Обязательная строка 1–64 символа, полное совпадение с `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`; уникальна в документе |
| `type` | Обязательное значение `markdown`, `html`, `css` или `javascript` |
| `title` | Необязательная строка 0–200 символов; нормализуется в `""` |
| `source` | Обязательная строка 0–100000 Unicode scalar values |
| `enabled` | Обязательный boolean для HTML/CSS/JavaScript; запрещён для Markdown |
| `metadata` | Обязательный объект; допустимые поля указаны ниже |

Метаданные ячейки: `comment` — необязательная строка 0–2000 символов, значение по умолчанию `""`; `collapsed` — необязательный boolean, по умолчанию `false`. Неизвестные сведения не сохраняются молча: импорт отклоняется с указанием пути поля. Расширение metadata потребует новой версии спецификации.

Редактор генерирует UUID для новых ячеек. Импорт допускает и короткие ID, например `cell-1` из ТЗ. При дублировании ячейки нужен новый ID; при копировании всего блокнота ID ячеек можно сохранить, поскольку область уникальности — документ.

## Лимиты

| Ограничение | Предлагаемое значение |
| --- | --- |
| Размер файла до JSON-разбора | 5 MiB = 5242880 байт |
| Размер канонической сериализации после нормализации | Не более 5 MiB |
| Максимальная глубина входного JSON | 16 уровней; корневой контейнер — уровень 1 |
| Количество ячеек | 200 |
| Длина `source` одной ячейки | 100000 символов |
| Сумма длин всех `source` | 1000000 символов |

Размер в байтах и количество символов — разные проверки. Длины строк считаются по Unicode scalar values; в JavaScript нельзя использовать обычное `.length` как эквивалент Python `len`. Эмодзи и не-BMP символы включаются в общие проверки. U+0000 исключён для совместимости с JSONB; особенности JSONB описаны в [PostgreSQL](https://www.postgresql.org/docs/current/datatype-json.html).

## Пример переносимого документа

```json
{
  "format": "web-notebook",
  "version": "1.0",
  "metadata": {"title": "Первый эксперимент", "description": "Активность CSS"},
  "cells": [
    {"id": "cell-1", "type": "markdown", "title": "Введение", "source": "# Проверка оформления", "metadata": {}},
    {"id": "cell-2", "type": "html", "enabled": true, "source": "<h1 id=heading>Привет</h1>", "metadata": {}},
    {"id": "cell-3", "type": "css", "enabled": false, "source": "h1 { color: blue; }", "metadata": {"comment": "Включите перед запуском"}},
    {"id": "cell-4", "type": "javascript", "enabled": true, "source": "console.log(document.querySelector('#heading').textContent)", "metadata": {}}
  ]
}
```

## Семантика активности

Фильтр исполнения: `type != markdown AND enabled == true`. Затем три группы сохраняют взаимный порядок исходного массива внутри каждой группы. Глобальный порядок смешанных типов не означает чередование выполнения HTML, CSS и JS: сначала весь HTML, затем CSS, затем JS.

Массовые команды изменяют только `enabled` программных ячеек. Код, названия, комментарии, порядок и Markdown не меняются. Отключение и сворачивание независимы. Активность входит в экспорт, сохранение и восстановление. Ни одна операция с активностью сама не запускает документ.

## Совместимость Python и TypeScript

Единый источник истины — эта спецификация, её JSON Schema 2020-12 и общий набор fixtures. На этапе 2 предлагается создать `schemas/webnb-1.0.schema.json`, а не две независимо развиваемые схемы. TypeScript-типы генерировать из schema; runtime-валидацию применять отдельно. Pydantic-модели строго реализуют те же ограничения; экспортируемую ими schema проверять на согласованность с контрактом. Pydantic поддерживает генерацию JSON Schema, что описано в [официальной документации](https://docs.pydantic.dev/latest/concepts/json_schema/).

JSON Schema описывает структуру и локальные лимиты. Уникальность поля `id` между объектами, сумму длин, исходный размер, повторные ключи и канонический размер проверяют отдельные семантические проверки. `uniqueItems` не заменяет уникальность ID. Defaults schema не считаются автоматически применёнными; нормализация явно добавляет только перечисленные необязательные поля.

Оба движка используют одинаковые коды ошибок и JSON Pointer пути: `invalid_json`, `invalid_format`, `unsupported_version`, `invalid_field`, `unknown_field`, `duplicate_cell_id`, `limit_exceeded`. Пользовательские сообщения — русские, исходный код ячейки не отражается в ошибке целиком.

Экспорт: UTF-8, компактные разделители, без ASCII-экранирования обычного Unicode, с экранированием обязательных JSON-символов; нормализованные необязательные поля присутствуют, ключи выводятся в порядке таблиц, завершающий LF. Для проверки round-trip сравниваются нормализованные данные и точный `source`, а не исходные пробелы JSON. Экспорт повторно проверяется по лимиту байт. Сортировка ячеек запрещена.

Техническая основа schema: [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core). Выбор конкретного генератора и runtime-валидатора будет проверен на совместимость до установки.
