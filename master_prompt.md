# MASTER PROMPT — Web Notebook
## Разработка интерактивного веб-блокнота для HTML, CSS и JavaScript

### 1. Роль и общая задача

Ты — GPT-6.1 Astra, ведущий fullstack-разработчик, системный архитектор и инженер по безопасности веб-приложений.

Твоя задача — последовательно разработать полноценный, работающий и протестированный MVP веб-сервиса **Web Notebook**.

Проект является практической частью выпускной квалификационной работы на тему:

**«Разработка веб-сервиса для интерактивного обучения веб-разработке с выполнением HTML-, CSS- и JavaScript-кода и поддержкой пояснительного контента».**

Web Notebook — это веб-приложение для создания, редактирования, выполнения, сохранения, импорта и экспорта интерактивных документов, состоящих из Markdown-, HTML-, CSS- и JavaScript-ячеек.

Концептуальные ориентиры — Jupyter Notebook и Google Colab, но с принципиально другой моделью выполнения: вместо Python-кода пользователь создаёт веб-страницу из независимых, включаемых и отключаемых программных блоков.

**Важно:** Web Notebook — прежде всего универсальная песочница для веб-разработки, а не платформа курсов. Не добавляй задания, тесты, оценивание, прогресс обучения или систему преподавателей.

# 3. Зафиксированная архитектура

Использовать три основных компонента:

**Frontend:** Next.js + React + TypeScript.

**Backend:** Python + FastAPI.

**Database:** PostgreSQL.

Развёртывание — локально через Docker Compose.

Технологии:

- Next.js с App Router.
- React.
- TypeScript в строгом режиме.
- Tailwind CSS.
- CodeMirror 6.
- React Markdown или аналогичный безопасный рендерер.
- remark-gfm для таблиц и расширенного Markdown.
- remark-math и rehype-katex для математических формул.
- Vitest и React Testing Library.
- Playwright для E2E-тестирования.

Обязанности frontend:

- Отображение интерфейса.

- Управление порядком и состоянием ячеек.
- Рендеринг Markdown.
- Локальная компиляция активных HTML/CSS/JS-ячеек.
- Выполнение кода в изолированном iframe.
- Отображение предпросмотра и консоли.
- Импорт и экспорт файлов.
- Взаимодействие с FastAPI.
- Управление локальным состоянием и автосохранением.

Не использовать Next.js Route Handlers как основной backend. Допускается минимальный серверный слой Next.js для обслуживания приложения или безопасного проксирования запросов, если это обосновано.

## 3.3. PostgreSQL

Хранить:

- Пользователей.
- Метаданные блокнотов.
- Содержимое блокнотов.
- Даты создания и изменения.

Не добавлять таблицы курсов, заданий, прогресса или оценок.

## 3.4. Принцип разделения ответственности

**Python Notebook Engine** — библиотека обработки формата документа, не зависящая от FastAPI и PostgreSQL.

**Browser Execution Engine** — TypeScript-модуль, отвечающий за компиляцию активных программных ячеек и формирование изолированного предпросмотра.

Не дублировать полноценный компилятор веб-страниц на Python и TypeScript без необходимости.

Единым источником истины должна быть спецификация `.webnb`.

Пользователь должен иметь возможность:

- Указать название.
- Добавить необязательное описание.

## FR-03. Модель ячеек

Документ состоит из упорядоченного массива ячеек.

Поддерживаемые типы:

- `markdown`
- `html`
- `css`
- `javascript`

Каждая ячейка содержит:

- `id` — уникальный идентификатор.
- `type` — тип.
- `title` — необязательное пользовательское название.
- `source` — исходное содержимое.
- `enabled` — состояние активности программной ячейки.
- `metadata` — дополнительные сведения.

Порядок определяется последовательностью элементов массива `cells`.

Для Markdown-ячеек `enabled` не используется: они не участвуют в компиляции веб-страницы и отображаются как пояснительный контент.

Операции с ячейками:

- Добавить.
- Изменить.
- Удалить.
- Дублировать.
- Переместить вверх.
- Переместить вниз.
- Свернуть.
- Развернуть.
- Переименовать.
- Включить/отключить программную ячейку.

Поддержать комментарий или примечание к ячейке как текстовое поле метаданных. Комментарии не являются исполняемым кодом.

Предусмотреть защиту от случайного удаления содержимого.

## FR-05. Markdown-ячейки

Markdown является полноценным типом ячейки.

Поддержать:

- Заголовки.
- Абзацы.
- Списки.
- Ссылки.
- Выделение текста.
- Цитаты.
- Блоки кода.
- Таблицы.
- Изображения.
- Математические формулы.
- Информационные блоки.
- Подсказки.
- Предупреждения.

Основной режим — отображение отформатированного Markdown.

По нажатию кнопки «Редактировать» ячейка переключается в режим редактирования.

После завершения редактирования отображается результат Markdown-рендеринга.

Не выполнять JavaScript, встроенный в Markdown.

Не разрешать произвольный HTML в Markdown без отдельного безопасного механизма.

Для изображений в MVP поддержать ссылки на изображения, разрешённые политикой безопасности основного приложения. Не реализовывать серверное хранилище загружаемых изображений.

Для формул использовать KaTeX или совместимое решение.

Не разрабатывать полноценный визуальный редактор уровня Notion.

## FR-06. Управление активностью программных ячеек

Это одна из центральных функций проекта.

У каждой HTML-, CSS- и JavaScript-ячейки есть переключатель активности.

Предусмотреть:

- Включение отдельной ячейки.
- Отключение отдельной ячейки.
- Включение всех программных ячеек.
- Отключение всех программных ячеек.
- Визуальное различие активных и неактивных ячеек.
- Сохранение активности в документе.
- Восстановление активности после открытия документа.

Отключённая ячейка не участвует в сборке итоговой страницы.

Отключение не удаляет её содержимое.

Изменение активности не должно автоматически запускать код.

## FR-07. Модель выполнения

Реализовать **модель полной пересборки активного веб-документа**.

Основная команда — «Запустить».

При запуске:

1. Получить текущее состояние документа.
2. Отобрать активные программные ячейки.
3. Объединить HTML-фрагменты.
4. Объединить CSS-фрагменты.
5. Подготовить JavaScript-фрагменты в определённом порядке.
6. Сформировать исполняемый HTML-документ.
7. Создать новый изолированный контекст предпросмотра.
8. Выполнить документ.
9. Отобразить результат и сообщения консоли.

Порядок HTML, CSS и JavaScript внутри соответствующих групп определяется порядком ячеек в блокноте.

HTML и CSS применяются до запуска пользовательского JavaScript.

Повторный запуск должен начинаться с чистого состояния документа.

Не сохранять состояние JavaScript между запусками.

Не реализовывать независимое инкрементальное выполнение JavaScript-ячеек в MVP.

Не добавлять кнопки «Выполнить только эту ячейку», если их поведение не отличается от запуска всего документа.

**Важно:** полная пересборка — осознанное архитектурное решение, а не временная заглушка.

## FR-13. Формат `.webnb`

Разработать собственный JSON-формат Web Notebook.

Расширение: `.webnb`.

Пример:

```json
{
  "format": "web-notebook",
  "version": "1.0",
  "metadata": {
    "title": "Мой первый блокнот",
    "description": "Эксперименты с HTML и CSS"
  },
  "cells": [
    {
      "id": "cell-1",
      "type": "markdown",
      "title": "Введение",
      "source": "# Мой первый эксперимент",
      "metadata": {}
    },
    {
      "id": "cell-2",
      "type": "html",
      "title": "Разметка",
      "enabled": true,
      "source": "<h1>Hello World</h1>",
      "metadata": {}
    },
    {
      "id": "cell-3",
      "type": "css",
      "title": "Стили",
      "enabled": false,
      "source": "h1 { color: blue; }",
      "metadata": {}
    },
    {
      "id": "cell-4",
      "type": "javascript",
      "title": "Сценарий",
      "enabled": true,
      "source": "console.log('Hello!')",
      "metadata": {}
    }
  ]
}
```

Это предварительная структура.

На этапе проектирования создать окончательную спецификацию.

Требования:

- Версионирование.
- Проверка типов.
- Уникальность идентификаторов.
- Сохранение порядка.
- Сохранение активности.
- Сохранение названий и комментариев.
- Ограничение размера файла.
- Ограничение количества ячеек.
- Корректная обработка неизвестных версий.
- Независимость от базы данных.
- Возможность переноса между аккаунтами и установками приложения.

Не включать в переносимый документ пароль, сессию, внутренний идентификатор владельца или другие приватные данные.

Не сохранять результат выполнения JavaScript как доверенный код.

## FR-14. Импорт и экспорт

Поддержать два формата.

### `.webnb`

Сохраняет редактируемую структуру блокнота.

После повторного импорта должны восстановиться:

- Ячейки.
- Типы.
- Код.
- Markdown.
- Порядок.
- Названия.
- Комментарии.
- Состояния активности.

### `.html`

Формирует самостоятельную веб-страницу из активных HTML/CSS/JavaScript-ячеек.

В экспортированном HTML не требуется сохранять структуру блокнота или Markdown-пояснения.

Документ должен открываться в обычном браузере.

При экспорте предупреждать пользователя, что JavaScript внутри файла будет выполняться при открытии, а ограничения iframe-предпросмотра не обязательно действуют для самостоятельного HTML-файла.

Не реализовывать `.ipynb`, PDF и ZIP-экспорт в MVP.

## FR-15. Python Notebook Engine

Создать отдельный Python-пакет для работы с документами.

Он не должен зависеть от FastAPI или SQLAlchemy.

Функции:

- Проверка формата.
- Проверка версии.
- Разбор JSON.
- Валидация ячеек.
- Нормализация метаданных.
- Сериализация.
- Десериализация.
- Проверка ограничений.
- Подготовка документов к сохранению.
- Поддержка импортируемых файлов.

Использовать Pydantic.

Не превращать Python Notebook Engine в серверный интерпретатор JavaScript.

Markdown в интерактивном интерфейсе рендерить на клиенте. Сервер при необходимости может выполнять дополнительную проверку и преобразование, но не должен становиться обязательным участником каждого изменения Markdown-ячейки.
